## Prioritized findings

### 1. HIGH: tablet breakpoint shrinks readable text and touch targets

Rules: R-03, Hallmark 75/39b. `dist/styles.css:98-109`.

At 700px, intro is 17px and buttons are 50px/48px tall. At 701px, desktop `--unit` scaling makes intro 11.68px, CTA 36.02px, and portfolio button 32.13px. At 768px, buttons remain 39.45px/35.19px. Whole desktop composition scales down instead of reflowing.

Normal-motion preference adds `scale:.9` to portfolio button (`dist/styles.css:207-209`), shrinking actual phone target from 48px to 43.20px; at 701px it becomes 28.91px. Additional evidence: `.hallmark/normal-motion-targets.json`. Main measurements above used reduced motion; normal-motion check used file URL for geometry only, not font validation.

Fix: keep stacked layout until two columns fit; clamp prose to readable minimum and keep interactive hit targets at least 44px. Remove resting button scale. Do not scale all dimensions through viewport width.

### 2. HIGH: portfolio focus ring fails contrast over photograph

Rules: R-32, Hallmark 26a/40. `dist/styles.css:13`, `dist/index.html:64`.

Hallmark measured peach outline at 1.93:1 against surrounding photograph at 1440px, below 3:1. All controls do receive instant focus outlines; this is contrast failure, not missing keyboard support.

Fix: use contrasting two-tone focus treatment or give this control a stable surrounding surface. Verify against actual photograph at each placement, not button fill alone.

### 3. HIGH: decorative animation loops indefinitely without pause

Rules: R-39, Hallmark 18. `dist/styles.css:225-228`.

Four wave effects run 9-19 seconds per iteration, infinitely. No pause control exists. Reduced-motion works (`animation-name: none`), but does not replace pause control for users who have not set that preference.

Fix: remove loops. Keep static wave composition if wanted; avoids adding another control for decoration.

### 4. HIGH: service content unavailable when JavaScript fails

Rules: Hallmark 62; R-35 resilience verification, C-4. `dist/index.html:65-67`, `dist/styles.css:45`, `dist/site.js:32-41`.

List starts hidden and inert. JavaScript is sole way to remove inert and reveal content. With scripting disabled, headline stays visible but all service details remain inaccessible. CTA also has no native contact destination.

Fix: use native `details`/`summary` for service disclosure, or ship list visible and progressively enhance collapse behavior. Real contact link can work without JavaScript.

### 5. HIGH: navigation offers unavailable login without warning at entry

Rules: R-24, R-38. `dist/index.html:23,77-79`.

Login button opens working modal, but modal only says sign-in unavailable. Feature status appears after clicking, not in navigation. No dead event handler or fake authentication claimed.

Fix: remove Login until needed, or label unavailable state before interaction. No authentication backend needed for this static portfolio.

### 6. HIGH, performance rule: hero image has no priority hint

Rule: R-40. `dist/index.html:63`.

Hero photograph has no `fetchpriority="high"`. Image loads successfully, is not lazy-loaded, and CSS reserves panel geometry with full-width/full-height absolute positioning. No measured layout shift or loading-time claim follows from this finding.

Fix: add high priority if photograph remains hero/LCP candidate. Width/height attributes documenting intrinsic aspect ratio are useful, but do not override intentional cover crop or claim existing geometry is unreserved.

### 7. LOW, functional completeness: primary action cannot start discussion

Rules: R-15, C-2. `dist/index.html:60,70-75`.

“Discuss a workflow” opens modal with no email, contact URL, fields, or send action. Placeholder is honest, so not fake send (Hallmark 70) and not literally dead control (R-26). Nevertheless page's main visitor task has no completion path.

Fix: supply real email or booking/contact URL. Native link is sufficient. Do not invent address or endpoint.

### 8. LOW: portfolio label promises work but reveals service categories

Rules: R-20, C-3. `dist/index.html:62-67`.

“Portofolio” reveals operational data, payroll/HRIS, and internal-tool service descriptions, not work examples. English page also uses Indonesian spelling while dialog return label says “portfolio.” Architecture photograph supplies mood, not evidence of stated work.

Fix: rename to “Areas of work” for smallest honest change. Add actual work only when supplied. Do not invent case studies, screenshots, or results.

### 9. HIGH, Hallmark Floor only: colors and fonts are not tokenized

Rules: Hallmark 48/20. `dist/styles.css:1-11,23-26,149-202`; SVG colors at `dist/index.html:30-42`.

38 mechanical literal findings include body-scoped custom properties, font declarations, hover colors, dialog colors, and gradients. Tokens belong in `:root` or declared theme block; components consume tokens. SVG colors also remain literal. CSS has no Hallmark audit/build stamp.

Fix: move palette/font definitions to token block and reuse them, including SVG stops. Stamp only after real checks, never fabricate pass. These are Hallmark system requirements, not browser rendering failures.

### 10. HIGH, Hallmark Floor only: overflow and grid safety rules absent

Rules: Hallmark 34/50. `dist/styles.css:10-11,19,99,119,124`.

Neither html nor body declares `overflow-x: clip`. Desktop sizing uses `100vw` in `--unit`; phone image-bearing grid uses bare `1fr`. Display heading lacks `overflow-wrap: break-word; min-width: 0`.

Fix: root/body clipping, content-relative sizing, `minmax(0, 1fr)` track, heading wrap safeguards. No horizontal overflow observed in current sampled widths; report missing safeguards separately from observed breakage.

### 11. HIGH, Hallmark house rule: hero has extra pre-heading text block

Rules: Hallmark 54/58. `dist/index.html:57-60`.

Greeting, heading, and intro produce three text blocks before action. Intro is 22 words across two sentences. Visible hero is not over 80 words, and no need to remove meaningful name simply to satisfy rule.

Fix: integrate Rey into heading/identity treatment and use one short explanatory sentence. Preserve identity and domain-specific facts. House rule, not accessibility defect.

### 12. LOW, finish and system consistency

Rules: R-31, Hallmark 24b/26b/39b/44c, F3/F16/F24. `dist/styles.css:17-25,76-80,98-116,199`.

22 off-scale spacing occurrences; duplicated desktop declarations and precise CTA left offset; no disabled styling; no explicit design rationale/dials; 74px/66px desktop controls exceed Hallmark 44-52px preference. At 1440x900 hero panel ends at y744, leaving 156px below. Heading lacks balance treatment; menu combines border and broad shadow; selection/scrollbar theme missing.

Fix only what helps chosen composition. Consolidate duplicated rules, align CTA through layout instead of negative left offset, document purposeful exceptions. No disabled controls currently ship, so missing disabled styling is future-state consistency issue, not broken active control. Compact one-screen portfolio does not need filler sections.
